## 3. Established Design Patterns & Conventions

### 1. Attribute-Based Dependency Injection (`JJS.Api`)
Services declare their own lifetime and interface using `[ServiceImplementation]`:
```csharp
[ServiceImplementation(typeof(IFooService), Lifetime = DependencyInjectionLifetime.Scoped)]
public class FooService : IFooService { ... }
```
`AppBuilder.RegisterAssemblyServices()` scans the assembly at startup to register types with `services.AddScoped/Singleton/Transient`. Manual registration in `Program.cs` is unnecessary.

### 2. Dapper Partial-Class Repository Pattern
Every entity data layer is partitioned into two files:
- `FooRepository.cs`: Interface, primary constructor, C# Dapper method implementations (`QueryAsync`, `ExecuteScalarAsync`).
- `FooRepository_Sql.cs`: `const string` definitions for raw SQL queries, parameterized SQL, and `MERGE` upserts.

### 3. In-Memory Caching (`ICacheService`)
- Centralized through `MemoryCacheService` (`System.Runtime.Caching`) with 20-minute sliding expiration.
- Cache keys are statically declared in `JJS.Api.Models.CacheKey` (`post/all`, `post/public`, `album-cache`, `comment/bypost`, `reaction/bypost`, etc.).
- Writes and admin refreshes explicitly invalidate cache keys via `Clear(key)` or `ClearByPrefix(prefix)`.

### 4. Authentication & User Provisioning Pipeline
1. **Frontend**: `@react-oauth/google` logs in -> Google ID Token stored in `sessionStorage` (`jjs_id_token`, `jjs_user`).
2. **Axios Interceptor**: `httpClient.ts` attaches `Authorization: Bearer <idToken>`.
3. **Backend JWT Middleware**: Validates token against `https://accounts.google.com` with configured `GoogleClientId`.
4. **`UserValidationMiddleware`**:
   - Skips CORS preflight `OPTIONS` requests.
   - Extracts email and name claims.
   - Queries `Users` table: auto-creates user with `Role = 'Guest'` on first visit; updates `LastActivityDate`.
   - Returns HTTP `403 Forbidden` if `IsDisabled == true` or `Blocked == true`.
   - Mutates `HttpContext.User` claims with database `Role` and `DisplayName` for downstream controllers.

### 5. Role-Based Access Control (RBAC)
- **`Admin`**: Full CRUD access across posts, recipes, users, photo albums, hidden comments, and uploads. Gated by `[Authorize(Roles = "Admin")]` and `<ProtectedRoute requiredRoles={[ROLE_ADMIN]} />`.
- **`CircleOfTrust`**: Access to private personal posts (`CircleOfTrust = 1`) and gated pages (`/things/wedding`).
- **`Guest`**: Standard authenticated user (can submit comments and react with emojis).
- **Public (Anonymous)**: Read-only access to public posts, recipes, photo albums, and public reactions.

### 6. Gemini AI Comment Moderation (`CommentModerationService`)
- Every submitted comment triggers `gemini-3.5-flash:generateContent`.
- Prompt instructs AI to return strict JSON: `{ "IsSpam": boolean, "IsToxic": boolean, "Reason": "..." }`.
- If flagged (`IsSpam || IsToxic`), comment is automatically stored as `AdminHidden = 1`, `ScreenedBy = "Gemini AI"`, `ScreenResult = <reason>`.
- Graceful degradation: if API key is missing or call fails, warning is logged and comment passes through for manual review.

### 7. Image Processing & Watermarking (`MetaDataService`, `ThumbnailService`)
- Ingested images resized to max 1920px width/height while preserving aspect ratio.
- EXIF metadata preserved: `XPTitle` / `ImageDescription` extracted for titles, `XPComment` for descriptions.
- `ExifTag.Copyright` stamped as `© 2006 - <Year> johnandjeri.com`.
- `ThumbnailService` generates and disk-caches 240x240 / 480x480 thumbnails on demand with HTTP caching headers.

### 8. Frontend Data Architecture (`jjs-web`)
- **Provider Hierarchy**:
  ```
  RootContextProvider
    └── JJSAuthProvider (Google OAuth, token validation, role helpers)
          └── RootContext (App-level messaging)
                └── ApiContextProvider (Axios HTTP verbs with auto-token injection)
                      └── MantineProvider (Theme: blue primary, Inter font)
                            └── RouterProvider (React Router v8)
  ```
- **Data Fetching**: SWR for dynamic lists and live interactions (optimistic reactions, comments); React Router `loader` functions for detail view preloading (`/post/:id`, `/recipe/:id`, `/admin/post/:id`, `/admin/recipe/:id`).
- **Form Handling**: `@mantine/form` with `mantine-form-zod-resolver` and Zod domain schemas (`postSchema`, `recipeSchema`, `commentSchema`).

- **`vw_cust_PostCategorySummary`**: Aggregates posts with comma-separated categories (`ConcatCategories`).

- **`vw_cust_IngredientsXrefSummary`**: Joins ingredients, units of measure, and recipe links.
- **`ConvertHtmlToMarkdown(html)`**: Scalar SQL function used in legacy migration to transform HTML body text to Markdown.
- **`SplitList(list, delimiter)`** / **`ConcatCategories(postId)`**: String manipulation utilities.

## 7. Repetitive Rules & Token Savers

### TypeScript & Vite Rules
- **Path Aliases**:
  - `@/*` -> `src/*`
  - `@lib/*` -> `src/lib/*`
  - `@api/*` -> `src/api/*`
  - `@components/*` -> `src/components/*`
  - `@pages/*` -> `src/pages/*`
- **Compiler Flags**: `verbatimModuleSyntax: true` requires explicit `import type { ... }` for type-only imports.
- **Enums**: Avoid TypeScript `enum`. Use const objects with `as const` and union types (e.g. `export const HttpVerb = { GET: 'GET', ... } as const;`).

### Mantine UI 9 & Styling Rules
- Global Mantine CSS must be imported in exact order in `App.tsx`:
  1. `@mantine/core/styles.css`
  2. `@mantine/carousel/styles.css`
- Component styling uses CSS Modules (`*.module.css`) with PostCSS (`postcss-preset-mantine` and `postcss-simple-vars`).
- Forms must use `@mantine/form` with `mantine-form-zod-resolver` and strict Zod schemas.

### Media & Large File Boundaries (Token Preservation)
- **Do NOT inspect or parse**:
  - Binary image/media folders: `JJS.Api/Albums/`, `*.jpg`, `*.png`, `*.gif`, `*.mp4`, `*.pdf`.
  - Database binary artifacts: `Database/*.dbmdl`, `Database/*.jfm`, `*.ldf`, `*.mdf`.
  - Build and publish outputs: `publish-output/`, `jjs-web/dist/`, `bin/`, `obj/`, `node_modules/`.
  - Huge lock files: `package-lock.json`.

### IIS & Production Deployment Mechanics
- **CI/CD (`.github/workflows/deploy.yml`)**:
  1. Restores and runs C# unit tests (`JJS.Api.Tests`).
  2. Publishes .NET WebAPI (`-c Release -r win-x86 -o ./publish-output/api`).
  3. Builds Vite UI (`npm run winhost` -> `jjs-web/dist/`).
  4. Deploys `app_offline.htm` via FTP to gracefully release IIS file locks.
  5. Deploys API binaries to root `/` (excluding `appsettings.*.json`).
  6. Deploys UI static assets to `/ui/`.
  7. Deploys `app_online.htm` to bring the site back online.
- **SPA Fallback Routing**: Handled in production by `Program.cs` (`MapWhen(!IS_DEBUG && !path.StartsWith("/api"))` serving `/ui/index.html`).
